# Generated Talent Tree Output Rules

- Keep one `<definition-name>.prefab` and `<definition-name>.json` pair per exported tree in this directory, with Unity `.meta` files alongside them.
- Both files are generated by merging the matching logic definition under `Editor/TalentTree/Definitions/` and UI layout under `Editor/TalentTree/Layouts/`. Do not hand-edit them; regenerate after either source changes.
- Patch-delivered prefabs must not introduce MonoBehaviour script types absent from the installed player. The current export uses the project's shipped `UILineRenderer` plus Unity built-in UGUI components; the matching JSON owns source GUID, node IDs, prerequisites, and edge IDs. Game code locates views by stable `Node <id>` and `Edge <from> to <to>/Active` names.
- The export computes a padded rectangular content size from node discs and Bezier curves, symmetric around the authored origin `(0,0)`. Prefab and JSON node positions must exactly match editor positions; `contentCenter` is zero. Do not include the six-sector editor guide. Give each directed edge a separate Graphic named `Edge <from> to <to>` so it can show its own activation state. Do not treat legacy `boardSize` as a fixed editor boundary.
- Each directed edge has a base `UILineRenderer` and a hidden `Active` child `UILineRenderer`. Endpoint/handle data is generated from the editor layout; color, line thickness, material, and other visual settings may be tuned in the prefab and must survive later exports for the same edge and state. The generated `Active` child is always hidden by default. Do not treat a manual prefab coordinate change as source geometry.
- Before replacing an existing prefab, verify its source definition GUID matches. Never overwrite an unrelated prefab or JSON file.
- Remove obsolete output pairs explicitly when their source definition is retired; do not bulk-delete this directory.
