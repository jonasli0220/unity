# Talent Tree Editor

Open **Tools > UI > Talent Tree > Open**. All editing happens in one canvas, while each tree saves to two source assets:

- **逻辑**: `Definitions/<name>.asset` owns stable node keys, table IDs, Small/Core types, and directed prerequisite connections. Right-click empty canvas space to add a node at the pointer, or use the left buttons to add one at a suggested location. Edit IDs and types in the right inspector, and right-click a source node to connect it to a target. Every incoming edge is a mandatory direct prerequisite; cycles and duplicate IDs are rejected.
- **表现**: `Layouts/<name>Layout.asset` references the logic asset and owns node positions and icons, Bezier handles, line and node styles. The editor canvas has no fixed radius; six sectors are visual guides that extend through the view. A new node immediately has a layout record and can be dragged. Older unplaced nodes also become draggable; the first drag creates their missing layout record. Drag on empty canvas space to box-select; drag any selected node to move the whole group. Shift-drag another box to add nodes; Shift/Ctrl-click a node to add or remove it. Click a connection, then drag either yellow Bezier handle to reshape it; an old connection without a curve record gains one on first drag. Right-click the selected connection to insert a Small or Core node at the curve midpoint while preserving its shape. Right-drag or middle-drag to pan; use the wheel to zoom around the pointer. **适应内容** frames the authored graph. Delete removes a selected edge. Deleting nodes reconnects surviving incoming prerequisites to surviving outgoing nodes and removes their old curve records; batch deletion follows the same rule across selected nodes.

The first time an existing combined definition is opened, click **创建表现配置**. The tool copies its old positions, icons, curve handles, and style into a new layout asset without rewriting the logic asset. After that, editing a graph field writes only the definition and editing a visual field writes only the layout. Ctrl+Z/Ctrl+Y can step through separate edits made during the current Unity Editor session; one node or Bezier drag is one Undo step, including a batch move. Obsolete layout entries are retained but ignored by export; missing entries must be synchronized or placed before export.

**检查** validates both assets and their relationship. **生成 Prefab + JSON** merges their current saved data into the pair under `Assets/Content/UI/Prefab/talent_tree/`; it does not modify either source. Export calculates padded rectangular bounds from node discs and Bezier curves and recenters the generated content. Unity's Force Text serialization keeps each node/edge layout as a stable YAML entry, so version control can usually merge edits to different entries. Simultaneous edits to the same entry still need review. Collaborators should merge the two source assets before one integration export publishes the generated pair, avoiding concurrent edits to the same output files.

The prefab contains a transparent viewport, a six-sector background clipped to the exported rectangle, batched curves, node UI, `TalentTreeData`, and `TalentTreePanZoom`. Place it under an existing Canvas and EventSystem. It does not implement unlocking, costs, save data, or activation visuals. The six equal sectors are visual guides only and add no sector field to nodes.

The version 3 JSON contains `sourceGuid` for the logic asset, `layoutGuid` for the UI asset, rectangular `contentSize`, authored `contentCenter`, compatibility `boardSize` (the longer side), `nodes`, and `edges`. Exported node `position` is relative to `contentCenter`; add `contentCenter` to recover its editor coordinate. Each node also has `id`, `type`, `iconAssetPath`, and sorted `prerequisiteIds`. Each edge has `fromId`, `toId`, `fromHandle`, and `toHandle`. The prefab's `TalentTreeData` exposes the same crop metadata, merged graph, and direct node-view references.

For a first look, run **Tools > UI > Talent Tree > Create Example Tree**. It creates or migrates the two example assets and rebuilds their output pair. **Run Graph Edit Checks** uses a disposable tree to test curve splitting, prerequisite bypass, missing curve recovery, and cropped prefab export without changing the example tree. **Run Validation Checks** tests distant coordinates, automatic crop, duplicate IDs, directed cycles, and missing UI layout. **Run 1000 Node Stress Check** verifies curve batching and removes only its own temporary assets.
