# Talent Tree Editor

Open **Tools > UI > Talent Tree > Open**. Click **打开已有** to pick a saved logic asset, or double-click a `TalentTreeDefinition` or matching `TalentTreeLayout` `.asset` in Unity's Project window. The editor reopens the last tree for this project when no source asset is selected. Selecting a generated talent-tree prefab and opening the tool resolves its source logic asset by GUID; the prefab remains generated output. All editing happens in one canvas, while each tree saves to two source assets:

- **逻辑**: `Definitions/<name>.asset` owns stable node keys, table IDs, Small/Core types, and directed prerequisite connections. Right-click empty canvas space to add a node at the pointer, or use the left buttons to add one at a suggested location. Edit IDs and types in the right inspector, and right-click a source node to connect it to a target. Every incoming edge is a mandatory direct prerequisite; cycles and duplicate IDs are rejected.
- **表现**: `Layouts/<name>Layout.asset` references the logic asset and owns node positions and icons, Bezier handles, line and node styles. The editor canvas has no fixed radius; six sectors are visual guides that extend through the view. A new node immediately has a layout record and can be dragged. Older unplaced nodes also become draggable; the first drag creates their missing layout record. Drag on empty canvas space to box-select; drag any selected node to move the whole group. Shift-drag another box to add nodes; Shift/Ctrl-click a node to add or remove it. Click a connection, then drag either yellow Bezier handle to reshape it; an old connection without a curve record gains one on first drag. Right-click the selected connection to insert a Small or Core node at the curve midpoint while preserving its shape. Right-drag or middle-drag to pan; use the wheel to zoom around the pointer. **适应内容** frames the authored graph. Delete removes a selected edge. Deleting nodes reconnects surviving incoming prerequisites to surviving outgoing nodes and removes their old curve records; batch deletion follows the same rule across selected nodes.

The first time an existing combined definition is opened, click **创建表现配置**. The tool copies its old positions, icons, curve handles, and style into a new layout asset without rewriting the logic asset. After that, editing a graph field writes only the definition and editing a visual field writes only the layout. Ctrl+Z/Ctrl+Y can step through separate edits made during the current Unity Editor session; one node or Bezier drag is one Undo step, including a batch move. Obsolete layout entries are retained but ignored by export. If old data or external edits leave nodes without positions or edges without curve records, **补齐位置和曲线** appears in the toolbar and context menu to add those missing visual records; normal new nodes and edges already create them automatically.

Large trees use indexed lookups while drawing and selecting, and offscreen curves are skipped. At whole-tree zoom, nodes become compact marks and nearly straight curves use simple lines; zooming in restores full node previews, Bezier shapes, arrows, and editable handles. This changes only the editor preview and leaves the saved graph, layout, and export geometry intact.

**检查** validates both assets and their relationship. **生成 Prefab + JSON** merges their current saved data into the pair under `Assets/Content/UI/Prefab/talent_tree/` and bakes line sprites into `<name>_Sprites/`; it does not modify either source. Export calculates padded rectangular bounds from node discs and Bezier curves around the editor origin. The prefab's centered `Content` and JSON positions share the same `(0,0)` coordinate system as the editor. Unity's Force Text serialization keeps each source node/edge layout as a stable YAML entry, so version control can usually merge edits to different entries. Simultaneous edits to the same entry still need review. Collaborators should merge the two source assets before one integration export publishes generated assets.

The exporter rasterizes inactive curves into transparent 2048 by 2048 world-unit tiles on a fixed grid with origin `(0,0)`. Each tile is a Sprite `Image` under `Content/InactiveTiles` at its exact grid center. Activated curves are cropped individually at two pixels per world unit and packed into multi-Sprite atlases up to 2048 pixels, each trimmed to power-of-two dimensions around used sprites; exceptionally long curves use a lower pixel density so they still fit one sprite. `Content/ActiveEdges` and `Content/Nodes` are empty layers in the exported prefab. The JSON gives each node's editor position and each edge's active image center, size, atlas path, sprite name, and pixel density. A controller already in the released player must create/reuse only visible node prefabs and active `Image` objects under those layers, set their `RectTransform.anchoredPosition` and `sizeDelta` from JSON, and recycle them when offscreen. The generated prefab adds no new runtime script or live curve Graphic. The editor's icon, fill, rim, and frame are authoring previews only. Place the prefab under an existing Canvas and EventSystem; the transparent viewport uses built-in `ScrollRect` for drag panning, and the embedding parent supplies clipping through its own mask.

Line width and color for both states are edited on the layout asset before export. Inspector changes to generated line assets or prefab Images are replaced on re-export. PNG import settings are Sprite, no mipmaps, and platform-compressed (Android/iPhone ASTC 4x4; Standalone DXT5). The source PNG stays readable as a transparent authoring artifact, while the imported player texture is compressed. Fixed tile coordinates prevent cropping offsets. The full 2,546-node sample previously exported 5,445 GameObjects, most of them empty placeholders. Version 6 removes those placeholders so opening and nesting the prefab has a small hierarchy; game code now must read JSON and mount only visible node and active-edge views. Code that searches for precreated `Node <id>` or `Edge <from> to <to>` children needs to migrate to this data-driven path.

The version 6 JSON contains `sourceGuid`, `layoutGuid`, rectangular `contentSize`, zero `contentCenter`, compatibility `boardSize`, `nodes`, `edges`, `inactiveTiles`, and `generatedAssets`. Exported node `position` equals its editor coordinate, with `id`, `type`, authored display `size`, `iconAssetPath` (editor preview metadata), and sorted `prerequisiteIds`. Mount the game's node prefab at the JSON position and scale it uniformly by `size / prefabRootWidth`; for the full PoE sample, 80-unit Small and 140-unit Core source prefabs both use a 0.3 scale to match 24- and 42-unit editor nodes. Each edge has `fromId`, `toId`, `fromHandle`, `toHandle`, `activePosition`, `activeSize`, `activeAtlasPath`, `activeSpriteName`, and `activePixelsPerUnit`. Each tile has grid `x/y`, `position`, `size`, and `assetPath`. Ship the JSON with the prefab so game code can create graph views and resolve active sprites. Existing version 5 JSON files can still be read by the editor to verify output ownership before replacement.

Re-export keeps the same output paths and `.meta` GUIDs for unchanged tiles and atlases. Inactive tiles use `Inactive_<x>_<y>.png`; active sheets use `ActiveAtlas_<x>_<y>_<page>.png`, grouped by fixed 2048-unit spatial buckets centered on the editor origin. It writes only changed PNG bytes, then removes obsolete PNGs listed by the previous validated JSON manifest after the new prefab and JSON are saved. Do not delete the entire sprite folder on each export: that would change GUIDs and force larger patches. Keep the source layout and definition as the reviewable edit history; generated assets should be produced by one integration export after source changes are merged. Back up or commit outputs before replacing a shipped version when a rollback is needed. Changes to the edge ordering within one bucket may repack that bucket's later atlas pages; atlas sheets are output artifacts, not stable per-edge IDs.

For a first look, run **Tools > UI > Talent Tree > Create Example Tree**. It creates or migrates the two example assets and rebuilds their output pair. **Run Graph Edit Checks** uses a disposable tree to test curve splitting, prerequisite bypass, missing curve recovery, baked sprite geometry, stable atlas GUIDs, and patch-safe prefab export without changing the example tree. **Run Validation Checks** tests distant coordinates, automatic crop, duplicate IDs, directed cycles, and missing UI layout. **Run 1000 Node Stress Check** verifies a larger bake and removes only its own temporary assets.
