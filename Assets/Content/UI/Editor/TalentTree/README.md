# Talent Tree Editor

Open **Tools > UI > Talent Tree > Open**. Click **打开已有** to pick a saved logic asset, or double-click a `TalentTreeDefinition` or matching `TalentTreeLayout` `.asset` in Unity's Project window. The editor reopens the last tree for this project when no source asset is selected. Selecting a generated talent-tree prefab and opening the tool resolves its source logic asset by GUID; the prefab remains generated output. All editing happens in one canvas, while each tree saves to two source assets:

- **逻辑**: `Definitions/<name>.asset` owns stable node keys, table IDs, Small/Core types, and directed prerequisite connections. Right-click empty canvas space to add a node at the pointer, or use the left buttons to add one at a suggested location. Edit IDs and types in the right inspector, and right-click a source node to connect it to a target. Every incoming edge is a mandatory direct prerequisite; cycles and duplicate IDs are rejected.
- **表现**: `Layouts/<name>Layout.asset` references the logic asset and owns node positions and icons, Bezier handles, line and node styles. The editor canvas has no fixed radius; six sectors are visual guides that extend through the view. A new node immediately has a layout record and can be dragged. Older unplaced nodes also become draggable; the first drag creates their missing layout record. Drag on empty canvas space to box-select; drag any selected node to move the whole group. Shift-drag another box to add nodes; Shift/Ctrl-click a node to add or remove it. Click a connection, then drag either yellow Bezier handle to reshape it; an old connection without a curve record gains one on first drag. Right-click the selected connection to insert a Small or Core node at the curve midpoint while preserving its shape. Right-drag or middle-drag to pan; use the wheel to zoom around the pointer. **适应内容** frames the authored graph. Delete removes a selected edge. Deleting nodes reconnects surviving incoming prerequisites to surviving outgoing nodes and removes their old curve records; batch deletion follows the same rule across selected nodes.

The first time an existing combined definition is opened, click **创建表现配置**. The tool copies its old positions, icons, curve handles, and style into a new layout asset without rewriting the logic asset. After that, editing a graph field writes only the definition and editing a visual field writes only the layout. Ctrl+Z/Ctrl+Y can step through separate edits made during the current Unity Editor session; one node or Bezier drag is one Undo step, including a batch move. Obsolete layout entries are retained but ignored by export. If old data or external edits leave nodes without positions or edges without curve records, **补齐位置和曲线** appears in the toolbar and context menu to add those missing visual records; normal new nodes and edges already create them automatically.

Large trees use indexed lookups while drawing and selecting, and offscreen curves are skipped. At whole-tree zoom, nodes become compact marks and nearly straight curves use simple lines; zooming in restores full node previews, Bezier shapes, arrows, and editable handles. This changes only the editor preview and leaves the saved graph, layout, and export geometry intact.

**检查** validates both assets and their relationship. **生成 Prefab + JSON** merges their current saved data into the pair under `Assets/Content/UI/Prefab/talent_tree/`; it does not modify either source. Export calculates padded rectangular bounds from node discs and Bezier curves around the editor origin. The prefab's centered `Content` keeps each node at exactly the same coordinate as in the editor. Unity's Force Text serialization keeps each node/edge layout as a stable YAML entry, so version control can usually merge edits to different entries. Simultaneous edits to the same entry still need review. Collaborators should merge the two source assets before one integration export publishes the generated pair, avoiding concurrent edits to the same output files.

The prefab uses the project's already-shipped `UnityEngine.UI.UILineRenderer` for one base Bezier curve per directed edge and a hidden `Active` child curve. Each node is an empty, zero-size `RectTransform` named `Node <id>` at its exact editor coordinate. Game code instantiates the corresponding node prefab under that anchor with local position zero; the editor's icon, fill, rim, and frame are authoring previews and are not exported as node visuals. The transparent viewport uses built-in `ScrollRect` for drag panning. No new TalentTree runtime script is attached to the generated prefab. In each line's Inspector, Color, Material, Line Thickness, Line Caps, Line Joins, and Bezier Segments Per Curve are editable. Re-export keeps those style settings per edge and state while refreshing the four Bezier control points from the layout. The node and edge IDs are stable hierarchy names (`Node <id>`, `Edge <from> to <to>/Active`); game code reads prerequisites from the paired JSON and can show an active edge with `Active.SetActive(true)`. Unity `Handles.DrawBezier` is editor-only. Place the prefab under an existing Canvas and EventSystem. Mouse-wheel zoom, unlocking, costs, and saving require integration with scripts that are already in the released player; a patch-only prefab cannot introduce new runtime code.

The version 4 JSON contains `sourceGuid` for the logic asset, `layoutGuid` for the UI asset, rectangular `contentSize`, zero `contentCenter`, compatibility `boardSize` (the longer side), `nodes`, and `edges`. Exported node `position` equals its editor coordinate. Each node also has `id`, `type`, `iconAssetPath` (editor preview metadata), and sorted `prerequisiteIds`. Each edge has `fromId`, `toId`, `fromHandle`, and `toHandle`. Ship the JSON alongside the prefab so existing game code can resolve graph logic; the prefab itself carries no new data script.

For a first look, run **Tools > UI > Talent Tree > Create Example Tree**. It creates or migrates the two example assets and rebuilds their output pair. **Run Graph Edit Checks** uses a disposable tree to test curve splitting, prerequisite bypass, missing curve recovery, patch-safe prefab export, and style preservation without changing the example tree. **Run Validation Checks** tests distant coordinates, automatic crop, duplicate IDs, directed cycles, and missing UI layout. **Run 1000 Node Stress Check** verifies independently exported curves and removes only its own temporary assets.
