# Talent Tree Editor Rules

- Keep all talent-tree tool C# and the tool README in this Editor directory, including legacy compatibility types formerly under `Runtime/TalentTree`. Preserve their script `.meta` GUIDs when moving them. Do not put current tool scripts back under `Runtime/TalentTree`; current generated prefabs use built-in UGUI and baked Sprites. Put `TalentTreeDefinition` graph assets in `Definitions/`, named for the tree, and `TalentTreeLayout` presentation assets in `Layouts/`, named `<definition-name>Layout`. Do not store generated prefabs or JSON here.
- A definition owns node keys, numeric table IDs, node types, and directed prerequisite edges. A layout owns node positions, icons, Bezier handles, and visual style. Link them by stable node keys and directed edge keys. The editor exposes all operations together and writes each change only to the asset that owns that field; do not gate editing by user role.
- Preserve legacy visual fields in definitions only for one-time migration into a layout. Do not use those fields for new edits or exports.
- Every edit must support Unity Undo. Edits to an existing node's ID or type mark only the definition dirty, and visual-only edits mark only the layout dirty. Topology edits that add/remove matching curve records mark both assets dirty in one Undo group. Keep serialized node/edge entry order stable so text merges can resolve edits to different records. Export is explicit and must validate before changing either generated output.
- A connection edit that changes graph topology also updates its paired curve records in the same Undo group. New connections must have immediately draggable Bezier handles; existing connections without layout records gain one on the first handle drag. Splitting a selected directed edge inserts a node at its Bezier midpoint and replaces it with two directed edges whose curves retain the original shape. Deleting a node reconnects its surviving incoming prerequisites to its surviving outgoing targets, skips self/duplicate edges, and removes retired visual records. Batch deletion follows the same bypass rule through removed nodes.
- Right-click node creation uses the clicked board coordinate and creates both graph and layout records in one Undo group. Newly created and previously unplaced nodes must be draggable without a separate sync action. Record drag changes when they occur, collapse one drag into one Undo step, and leave separate user actions as separate Undo steps across the current Unity Editor session.
- The editor canvas is unbounded for finite coordinates: do not clamp positions or group drags to a fixed board radius. Draw six sectors as editor-only guides extending through the visible canvas. Keep the serialized legacy `boardSize` only for migration, not as an authoring limit. Export calculates padded content bounds from nodes and Bezier curves around the authored origin, so prefab node coordinates match editor coordinates and `(0,0)` stays centered. Never export the sector guide.
- Export reads and validates both assets without modifying either. Missing layout entries must produce an actionable error rather than silently writing to the UI-owned asset.
- Bake exported Bezier geometry from layout endpoints and handles. Composite inactive curves into deterministic 2048-unit tiles with exact world-to-pixel mapping. Bake activated curves separately into cropped sprites packed in deterministic atlases no larger than 2048 pixels; trim each atlas to its used power-of-two dimensions. Export each edge's stable ID, position/size, and atlas sprite key in JSON. The prefab shows inactive tile Images and has empty `ActiveEdges` and `Nodes` layers; runtime code supplied in the player creates only visible views from JSON. Do not export per-edge/per-node placeholders or thousands of live `UILineRenderer` components.
- Export generated PNGs only under `<definition-name>_Sprites/` beside the prefab/JSON pair. Group active atlases by fixed 2048-unit spatial buckets so a local edit does not repack the whole tree. Use stable tile and bucket/page filenames, update changed files in place to preserve `.meta` GUIDs, and record the exact generated asset list in the paired JSON. Remove only stale files named by a validated previous manifest after the new pair is saved successfully. Never delete the whole folder or unrelated assets. Configure PNG importers for Sprite and platform texture compression.
- Patch-safe prefabs may reference only Unity built-in runtime components. Do not attach this tool's new runtime MonoBehaviours to generated prefabs. Keep graph IDs, positions, and prerequisites in the paired JSON; use `ScrollRect` for native panning. Do not export `Mask` or `RectMask2D`; the embedding parent prefab owns viewport clipping. Dynamic activation/viewport loading requires code already shipped in the player.
- Export no per-node GameObjects. Keep an empty `Content/Nodes` RectTransform layer for game integration to populate from JSON. Keep editor icon and node appearance settings for authoring preview only. Preserve node IDs, types, exact authored positions, authored display sizes, and prerequisites in JSON. The game can scale its node prefabs to the exported display size without changing the source prefab assets.
- Name authoring actions by their visible result. In Unity `GenericMenu`, `/` creates a submenu, so plain action labels must not contain slash characters. Show legacy layout repair only when node positions or curve records are missing, and describe it as filling those records; normal new nodes and edges create them automatically.
- Saved definitions and matching layouts must reopen without recreating data: the window offers an obvious asset picker, Project double-click on either source asset opens the editor, and reopening the window restores the last valid definition for this project when no source asset is selected. Generated prefabs resolve their source definition by the paired JSON GUID (legacy prefab data is supported for migration) but remain generated output, not authoring data.
- Keep temporary previews, logs, and stress-test data in `Library/Dragon/TalentTree`; remove them after validation. Do not commit them.
- Keep the authoring window responsive on multi-thousand-node trees: build direct node/layout/edge lookups for canvas work, avoid repeated linear searches inside draw and hit-test loops, cull offscreen geometry, and skip visually insignificant detail at overview zoom. Rebuild lookups after source changes so Undo and newly created records remain visible.
- When a definition is retired, remove its paired layout and generated prefab/JSON together after checking ownership. Never clean unrelated files by wildcard.
