# Talent Tree Editor Rules

- Keep authoring-only C# and the tool README in this directory. Put `TalentTreeDefinition` graph assets in `Definitions/`, named for the tree, and `TalentTreeLayout` presentation assets in `Layouts/`, named `<definition-name>Layout`. Do not store generated prefabs or JSON here.
- A definition owns node keys, numeric table IDs, node types, and directed prerequisite edges. A layout owns node positions, icons, Bezier handles, and visual style. Link them by stable node keys and directed edge keys. The editor exposes all operations together and writes each change only to the asset that owns that field; do not gate editing by user role.
- Preserve legacy visual fields in definitions only for one-time migration into a layout. Do not use those fields for new edits or exports.
- Every edit must support Unity Undo. Edits to an existing node's ID or type mark only the definition dirty, and visual-only edits mark only the layout dirty. Topology edits that add/remove matching curve records mark both assets dirty in one Undo group. Keep serialized node/edge entry order stable so text merges can resolve edits to different records. Export is explicit and must validate before changing either generated output.
- A connection edit that changes graph topology also updates its paired curve records in the same Undo group. New connections must have immediately draggable Bezier handles; existing connections without layout records gain one on the first handle drag. Splitting a selected directed edge inserts a node at its Bezier midpoint and replaces it with two directed edges whose curves retain the original shape. Deleting a node reconnects its surviving incoming prerequisites to its surviving outgoing targets, skips self/duplicate edges, and removes retired visual records. Batch deletion follows the same bypass rule through removed nodes.
- Right-click node creation uses the clicked board coordinate and creates both graph and layout records in one Undo group. Newly created and previously unplaced nodes must be draggable without a separate sync action. Record drag changes when they occur, collapse one drag into one Undo step, and leave separate user actions as separate Undo steps across the current Unity Editor session.
- The editor canvas is unbounded for finite coordinates: do not clamp positions or group drags to a fixed board radius. Draw six sectors as editor-only guides extending through the visible canvas. Keep the serialized legacy `boardSize` only for migration, not as an authoring limit. Export calculates padded content bounds from nodes and Bezier curves around the authored origin, so prefab node coordinates match editor coordinates and `(0,0)` stays centered. Never export the sector guide. Export each directed edge as a separate Graphic with a stable hierarchy name for independent runtime states.
- Export reads and validates both assets without modifying either. Missing layout entries must produce an actionable error rather than silently writing to the UI-owned asset.
- Exported Bezier geometry (endpoints and handles) always comes from the layout. Each edge owns a visible base UGUI curve and a hidden `Active` child curve. Style fields such as color, width, and material are editable on the prefab; re-export must preserve those fields per existing edge and state while replacing geometry from the layout. Do not preserve prefab-side coordinate edits. Use a new default style only when no previous edge state exists.
- Patch-safe exports may reference only Unity built-in runtime components and `UILineRenderer` already shipped under `Assets/Scripts/SgrProject/UI/UnityExtension/UI/Components/`. Do not attach this tool's new runtime MonoBehaviours to generated prefabs. Keep graph IDs and prerequisites in the paired JSON and stable hierarchy names; use `ScrollRect` for native panning. Zoom and activation wiring require shipped game logic.
- Export each talent node as an empty, zero-size `RectTransform` named `Node <id>` at its exact authored coordinate. Do not export node fill, rim, frame, icon, CanvasRenderer, or other visual children; game integration instantiates the corresponding node prefab under this anchor. Keep editor icon and node appearance settings for authoring preview only. Preserve node IDs, types, positions, and prerequisites in JSON.
- Name authoring actions by their visible result. In Unity `GenericMenu`, `/` creates a submenu, so plain action labels must not contain slash characters. Show legacy layout repair only when node positions or curve records are missing, and describe it as filling those records; normal new nodes and edges create them automatically.
- Saved definitions and matching layouts must reopen without recreating data: the window offers an obvious asset picker, Project double-click on either source asset opens the editor, and reopening the window restores the last valid definition for this project when no source asset is selected. Generated prefabs resolve their source definition by the paired JSON GUID (legacy prefab data is supported for migration) but remain generated output, not authoring data.
- Keep temporary previews, logs, and stress-test data in `Library/Dragon/TalentTree`; remove them after validation. Do not commit them.
- When a definition is retired, remove its paired layout and generated prefab/JSON together after checking ownership. Never clean unrelated files by wildcard.
